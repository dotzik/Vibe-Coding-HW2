# Decision record — redesign profilu na skill / subagent / hook (2026-05)

Extrakt klíčových rozhodnutí z brainstorm plánu `Plans/redesign-2026-05.md`
(dokument SPLNĚN 2026-05-17, poté smazán — historie v gitu).

**Why:** Monolitický „univerzální analytik 7 connectorů" nabobtnával hlavní kontext
(audit CONN-237 spotřeboval desítky tisíc tokenů), workflow se opakovaly ručně,
refactoring / dead-code / bug reporting neměly gates ani šablony.

## Rozhodnuto

- **Architektura:** profil rozsekán na specializované jednotky — **skill** (znovupoužitelný
  workflow s šablonami), **subagent** (izolovaný kontext, read-only deep work, paralelizace),
  **hook** (harness automatizace na event). Výsledek 2.0.0: 11 skills + 5 subagentů + 4 hooky.
- **Varianta A** (vše v jednom profilu, `.claude/skills` + `.claude/agents`) — zvolena proti
  variantě B (sourozenecké profily Doc-Curator / Bug-Hunter). Důvod: rychlá iterace, jeden git
  repo, snadné vzájemné odkazování. Re-evaluace po 2–3 měsících, jestli některá specializace
  dorostla na samostatný profil.
- **Bug hunting splitnut** na 3 subagenty — `bug-hunter` + `perf-hunter` + `security-auditor`
  zvlášť, ne jeden universal (universal by byl slabší — různé domény vyžadují různé patterny).
- **Refactor kategorie:** 3 buckety — kosmetic / structural / breaking — každý s vlastním gate.
- **Test/verify krok** doplněn jako samostatný workflow (build + smoke) — dřív manuální.
- **Jira workflow:** interactive gate — uživatel schválí issue body před založením přes MCP.
- **Worklog:** automatizace přes skill, ne full-auto Excel watch.

## How to apply

- Při dotazu na *proč* je profil takto strukturovaný → tento záznam.
- Re-evaluaci varianty A/B otevřít cca 2026-07/08 (2–3 měsíce po 2.0.0).
- Aktuální stav skills/subagentů/hooků = `CLAUDE.md`, ne tento historický záznam.
